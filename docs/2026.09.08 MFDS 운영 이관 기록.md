# MFDS 운영 이관 기록

## 이관 범위와 확인 결과

개발 원본 수집 이력을 운영에 복제했다. 개발과 운영 모두 Flyway V11~V13이 적용돼 있으며, 복제 대상 테이블의 컬럼·타입·기본값·collation이 일치했다. 운영의 기존 원장·정제·매칭 데이터는 0건이었다.

- 고유 RCNO: 13,111건
- 관측 처리일 범위: 2023.07.03~2026.09.07
- RCNO 형식 오류 및 원본 참조 누락: 0건
- 수동 정제 검토 및 수동 매칭 선택: 0건
- 원본 응답 압축 데이터: 299,386,577 bytes

개발의 알코올 ID를 운영에 그대로 적용하지 않았다. 공통 숫자 ID 중 이름·도수·용량 해시가 다른 알코올은 3,205건, 이름 해시가 다른 증류소는 7건이었다. 운영의 알코올·증류소·리전 기준 테이블은 변경하지 않았으며, 매칭 결과는 운영 DB로 재계산한다.

## 복제 방식

개발은 repeatable-read 읽기 전용 트랜잭션에서 읽고, 운영은 단일 트랜잭션으로 반영했다. 참조 무결성 검사를 비활성화하지 않았다. 원본 Job·Task·Fetch·Item의 ID는 대상 테이블이 비어 있음을 확인한 뒤 보존했다.

수입사는 공식 업소코드로 대응하고, 기존 운영 상호·인허가번호 일치를 확인했다. 기존 운영 수입사 368건은 모든 컬럼 값이 유지됐고 22건만 추가했다. RCNO 연결의 importer_id는 이 대응표로 변환했다. 개발의 정제 결과·매칭 후보·선택 이력·별칭은 복사하지 않았다.

복제 후 트랜잭션 안에서 정렬된 전체 행의 SHA-256을 비교한 뒤 커밋했다. 해시는 컬럼 순서의 nullable byte 배열을 JSON 직렬화한 값을 PK 순서로 연결해 계산했다. 연결 테이블 해시는 운영 importer_id로 변환한 값 기준이다.

## 초기 실행에서 발견한 설정 문제

정규화의 기본 lease는 5분인데 일일 Job은 최대 10,000건을 한 번에 claim한다. 운영 초기 실행의 처리 속도로는 만료 전에 전체 처리가 어려워 첫 Job을 중단했다. 완료된 NORMALIZED 599건과 REVIEW_REQUIRED 23건은 보존했다. 해당 matching run 1은 중단 사유와 함께 FAILED로 기록했고 기존 claim이 모두 만료된 후 재개했다.

운영 전용 ConfigMap에서 normalization.lease_duration을 2h로 설정한다. Job activeDeadlineSeconds도 7200이다. ConfigMap은 정규화 컨테이너의 /app/data/config.yaml에 읽기 전용으로 마운트한다. 동시 실행은 CronJob의 Forbid 정책을 유지한다. 장기적으로 배치 내 lease 갱신 또는 작은 단위의 반복 claim을 검토할 수 있다.
